# 유튜브 수집·직접 등록 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 사용자 요청 없이 병렬 에이전트를 시작하지 않는다.

**Goal:** 서연 개인 직캠과 외부 출연 콘텐츠를 자동 발견하거나 URL로 직접 등록하고 유튜브 탭에 모은다.

**Architecture:** Worker에서 YouTube Data API를 호출하고 D1에 영상 정보와 사용자 판정을 분리해 저장한다. 자동 발견과 직접 등록은 같은 영상 ID를 공유하고 기존 피드 조회 뷰에 유튜브를 추가한다. 직접 등록·탭을 먼저 완성하고 자동 수집·검토함을 연결한다.

**Tech Stack:** 기존 JavaScript ES modules, Cloudflare Workers/D1, HTML/CSS/vanilla JS, node:test. 새 프레임워크·유료 수집 공급자는 추가하지 않는다.

**Spec:** 이 문서의 요구사항과 설계를 이번 기능 명세로 사용하며 `docs/SPEC.md`, `DESIGN.md`, `AGENTS.md`를 함께 따른다.

작성일: 2026-09-21. 상태: **구현·배포·첫 예약 수집 검증 완료**. 2026-09-21 사용자가 계획대로 구현을 승인했다. 운영 결과는 docs/VALIDATION.md에 기록한다.

## Global Constraints

- 기존 Cloudflare Access 보호와 소유자 인증을 유지한다.
- 원본 영상 파일을 다운로드·저장·중계하지 않는다. 메타데이터와 원문 링크만 다룬다.
- 수집 응답 전체의 처리가 끝나고 저장이 성공한 뒤에만 cursor를 전진한다.
- 자동 수집·직접 등록·재조회는 기존 사용자 판정을 덮어쓰지 않는다.
- API 키·인증 정보·공급자 오류 원문을 저장소, 브라우저 응답, 로그에 남기지 않는다.
- 로컬 테스트, 실제 API 호출, 비공개 배포 확인 결과를 구분한다.
- 사용자 승인에 따라 구현·관련 검증·커밋·푸시·기존 환경 배포 확인을 수행한다. Access와 기존 공개 읽기 범위를 변경하지 않는다.

## 1. 요구사항과 제안 기본값

확정 범위:

- 탭은 `사진 / 영상 / 유튜브`로 구분한다.
- 음악방송은 **서연 개인 직캠만** 포함한다. 단체 무대는 제외한다.
- 서연이 출연한 외부 채널 예능·인터뷰·게스트 콘텐츠를 포함한다.
- Shorts는 제외하고 일반 영상 위주로 모은다.
- 자동 검색 누락을 보완하는 유튜브 URL 직접 등록을 제공한다.
- 무신사 출연 영상은 사용자가 기억한 예시다. 정확한 URL·출연자·채널은 확인 전이므로 초기 데이터로 단정하지 않는다.

| 항목 | 제안 기본값 |
|---|---|
| 첫 화면 | 사진 탭. 기존 media=all 주소는 사진으로 정규화 |
| 사진·영상 | 기존 X/Instagram 분류 유지. 혼합 게시물은 양쪽 표시 가능 |
| 유튜브 | platform=youtube만 표시. 썸네일 때문에 사진 탭에 섞지 않음 |
| 재생 | YouTube 원문을 새 탭으로 열기. 자체 재생·임베드는 1차 제외 |
| 직접 등록 | URL 조회 → 미리보기 → 종류·출연·일반 영상 확인 → 등록 |
| 자동 수집 | 검토함에 저장하고 사람이 확인한 뒤 게시 |
| 종류 | 개인 직캠 / 외부 출연 |
| 제외 | Shorts·단체 무대·다른 멤버·팬 편집본·재업로드 |
| 검색 일정 | 하루 2회, 검색어 3개, 검색어당 최대 2페이지 |
| 채널 일정 | 확인된 채널만 6시간마다 업로드 목록 조회 |
| 과거 범위 | 최초 최근 30일, 이후 최근 7일을 겹쳐 검색. 전수 과거 수집은 제외 |

문서 작성을 중단하지 않고 위 기본값을 제안한다. 초기 채널 목록과 실제 운영 할당량은 활성화 전에 확인한다.

## 2. 공식 수집 경로와 한계

공식 문서 확인일은 2026-09-21이며 실제 API 키를 사용한 응답은 아직 검증하지 않았다.

1. **키워드 발견:** `search.list(part=snippet,type=video)`에 `윤서연 직캠`, `tripleS SEOYEON fancam`, `트리플에스 서연`을 사용한다. 제목에 이름이 없는 외부 출연은 누락될 수 있다.
2. **채널 업로드:** `channels.list(part=contentDetails)`로 uploads playlist ID를 얻고 `playlistItems.list`로 확인한다. 최신 업로드를 검색 API만으로 추적하지 않는다.
3. **상세 조회:** `videos.list(part=snippet,contentDetails,status)`로 제목·채널·게시일·썸네일·길이·공개 상태를 확인한다. 서버 전용 API 키를 사용한다.
4. **할당량:** 현재 검색 문서는 Search Queries 버킷과 기본 일일 100회를 설명한다. 과거의 검색 1회=100 units 가정을 고정하지 않는다. 실제 프로젝트 quota를 확인하고 앱 자체 검색 상한을 일일 12회로 시작한다.
5. **Shorts:** `videoDuration=long`은 일반 영상 분류가 아니다. 짧은 개인 직캠을 누락시키므로 길이만으로 제외하지 않는다. 명확한 Shorts 여부 필드가 없어 최종 형식 확인은 사람이 한다.

근거: [검색 API](https://developers.google.com/youtube/v3/docs/search/list), [상세 조회](https://developers.google.com/youtube/v3/docs/videos/list), [채널 API](https://developers.google.com/youtube/v3/docs/channels), [업로드 목록 API](https://developers.google.com/youtube/v3/docs/playlistItems/list).

## 3. 직접 등록

- 기존 자료 관리 URL 입력창을 사용한다. X/Instagram은 기존 경로를 유지하고 YouTube만 새 등록 API로 보낸다.
- `youtube.com/watch?v=`, `www.youtube.com/watch?v=`, `m.youtube.com/watch?v=`, `youtu.be/`를 허용한다. ID는 11자리 `[A-Za-z0-9_-]`로 검사하고 `https://www.youtube.com/watch?v=ID`로 정규화한다. 추적·재생 시작·목록 파라미터는 제거한다.
- `/shorts/`, 재생목록만 있는 링크, 임의 도메인, 사용자정보 포함 URL, 비표준 포트는 거절한다. 입력 URL을 서버가 직접 fetch하지 않는다.
- 미리보기에서 제목·썸네일·채널·게시일·길이를 보여준다. 사용자가 개인 직캠/외부 출연을 선택하고 서연 출연 및 일반 영상임을 확인한 뒤 등록한다. 사용자 판정은 YouTube 제공 정보와 구분한다.
- 새 영상은 확인된 직접 등록으로 게시한다. 기존 pending/held/excluded 항목이면 판정을 보존하고 검토 화면으로 안내한다. 같은 URL 등록으로 제외 상태를 우회하지 않는다.
- 조회 실패 시 입력 URL을 유지하고 실패 이유·재시도를 보여준다. 새 항목을 게시 완료로 처리하지 않는다. 키 미설정은 설정 필요, 삭제/비공개는 조회 불가로 구분한다.
- 클라이언트가 보낸 제목·썸네일을 신뢰하지 않는다. 등록 시 서버에서 얻은 값을 저장한다.

## 4. 자동 수집·검토·중복

- 모든 발견은 검토 대기로 저장한다. 실제 작성 채널과 발견 경로(검색어/채널)를 별도 보관한다.
- 동일 영상 ID만 합친다. 제목·썸네일 유사성으로 다른 영상 ID를 합치지 않는다.
- 판정 `pending / kept / excluded / held`, 종류 `fancam / appearance`, 형식 `unknown / regular / shorts`를 분리한다. kept+regular+종류 확정+available만 피드에 표시한다.
- 길이·제목은 검토 단서다. 자동 출연 확정·얼굴 인식·LLM 분류는 도입하지 않는다.
- 재발견·정보 갱신·수동 등록은 기존 판정과 revision을 덮어쓰지 않는다. 동시 등록도 같은 PK에 병합한다.
- 페이지 전체 데이터 저장과 page token 갱신을 동일 D1 batch에 넣는다. 상세 조회 또는 저장 실패 시 해당 페이지를 완료하지 않는다. 정상 상세 응답에서 빠진 ID는 unavailable로 기록해 무한 재시도를 막는다.
- 소스별 lease token과 revision을 검사하며 만료된 작업은 저장·커서 갱신을 못 하게 한다. 페이지 제한에 닿으면 partial 상태와 다음 token을 보존한다.
- 검색 창 시작/종료와 page token을 저장해 재개한다. 검색 완료는 해당 창의 응답 처리 완료를 뜻하며 전체 영상 수집 완료를 뜻하지 않는다.

## 5. 데이터와 API 계약

아래는 신규 계약이며 현재 존재하는 함수가 아니다.

```js
parseYouTubeUrl(input) // -> {videoId, canonicalUrl}; invalid_url 오류
fetchYouTubeVideos(env, ids, {fetcher}) // -> {videos, unavailableIds}
previewYouTube(env, {url}, {fetcher}) // 미리보기, 쓰기 없음
registerYouTube(env, {url, category, confirmedRegular, requestId}, actor)
reviewYouTube(env, videoId, {revision, decision, category, format, reasonCode, requestId}, actor)
collectYouTube(env, {now, fetcher}) // disabled/idle/partial/ok/failed
refreshYouTube(env, {now, fetcher}) // 갱신·만료 처리 결과
```

| 저장소 | 필드와 책임 |
|---|---|
| youtube_videos | video_id PK, metadata_json, metadata_fetched_at, availability, decision, category, format, manual, revision, created_at, reviewed_at. API 캐시와 사용자 판정을 분리 |
| youtube_discoveries | video_id+source_key UNIQUE, 최초/최근 발견 시각 |
| youtube_sources | 검색/채널 설정, enabled, next_due_at, last_success_at, window_start/end, page_token, lease_token/until, revision, last_error_code |
| youtube_api_budget | 일자·버킷별 예약 호출 수. 요청 전 원자적 예약, 실패 호출도 집계 |
| youtube_review_events | request_id UNIQUE, fingerprint, 이전/이후 판정, video_id, 서버 인증 actor, 사유, 시각. append-only, API 제목·썸네일을 이력에 복제하지 않음 |

- `youtube_feed_posts`는 적격 항목을 기존 피드 형태로 변환한다. `id=yt:VIDEO_ID`, `platform=youtube`, `media.kind=video`, title/channelTitle/durationSeconds를 제공한다.
- `managed_feed_posts`에 UNION ALL로 추가하고 기존 X/Instagram/직접 등록의 제외·중복 규칙은 유지한다.
- `publicPost`에 추가 공개 필드를 명시적으로 투영한다. 수집 설정·키·검토 actor·내부 오류는 공개하지 않는다.
- 기존 감사 테이블은 platform CHECK가 X/INSTAGRAM만 허용한다. 전용 유튜브 이벤트를 사용하고 검토 내역 API에서 기존 이벤트와 UNION해 전역 날짜·ID 순서로 페이지 조회한다. 기존 감사 테이블/트리거를 재생성하지 않는다.
- 신규 API: `POST /api/youtube/preview`, `POST /api/youtube/posts`, `GET /api/youtube/review`, `PATCH /api/youtube/review/:id`.
- 모든 유튜브 관리 API는 owner 전용이다. 변경 API는 동일 Origin·관리 액션 헤더·JSON·본문 크기 제한을 적용한다. GET은 수집을 실행하지 않는다.
- 등록/검토는 requestId 멱등성을 보장한다. 동일 ID·다른 내용은 409. revision 충돌은 409. 판정 변경과 감사 이벤트를 원자적으로 저장한다.
- 오류: 입력 400, 인증 401/403, unavailable 영상 422, 충돌 409, 앱 호출 제한 429, 공급자 장애/키 미설정/quota 소진 503. 오류 코드는 원인을 구분하되 공급자 원문은 반환하지 않는다.

## 6. 운영과 갱신

- `YOUTUBE_API_KEY`는 Worker secret이다. `YOUTUBE_ENABLED`, `YOUTUBE_COLLECTION_ENABLED`를 별도로 두고 기본 off로 배포한다. 자동 수집을 꺼도 직접 등록과 메타데이터 갱신은 독립적으로 작동한다.
- 제안 상한: 검색 12회/일, 페이지 크기 50, 실행당 검색 최대 2회·상세 영상 최대 50개, 직접 등록 owner당 10회/분. 상세/채널 호출은 500회/일에서 직접 등록용 100회를 남긴다. 실제 프로젝트 quota가 더 작으면 낮춘다.
- quota 재설정 기준은 실제 Google 프로젝트 기준으로 맞춘다. 429/네트워크/5xx는 제한된 backoff, quota 소진은 재설정까지 중지, 키 권한 오류는 관리자 확인 전 반복 호출하지 않는다.
- 기존 5분 예약 실행에 due 작업 한 단위를 연결한다. 실제 검색/채널 간격은 DB next_due_at으로 관리하며 기존 X/Instagram Cron 분기를 유지한다.
- 메타데이터는 7일 주기로 재조회하고 30일 이내 갱신 또는 제거한다. 30일간 갱신 실패하면 API 제목·썸네일·설명 캐시를 제거하고 피드에서 제외한다. 신규 유튜브 API 캐시에만 적용하며 기존 프로젝트 원본을 삭제하지 않는다.
- 삭제/비공개가 정상 API 응답으로 확인되면 노출을 중단한다. 일시 장애로 영상 삭제를 확정하지 않는다. 사용자 입력·독립 판정 기록은 API 캐시와 분리한다.
- API 활성화 전 개인정보 안내·YouTube 출처 표기·갱신 정책을 확인한다. [개발자 정책](https://developers.google.com/youtube/terms/developer-policies)의 API 데이터 갱신 요구를 반영한다.
- 운영 화면에 성공 시각·중지·오류·검토 대기 수·갱신 상태를 표시한다. 기존 자동 알림에 새 항목을 확장하는 것은 1차 범위에서 제외한다.
